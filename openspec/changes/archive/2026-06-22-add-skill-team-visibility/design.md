## 2. 详细设计

### 2.1 枚举设计：SkillVisibility

**文件**: entity/SkillVisibility.java

`java
public enum SkillVisibility {
    PUBLIC,   // 公共对全平台可见
    PRIVATE,  // 私人仅创建者可见
    TEAM      // 团队可见（新增）
}
`

### 2.2 实体设计：Skill

**文件**: entity/Skill.java

| 字段名 | 类型 | 说明 | 约束 |
|--------|------|------|------|
| id | Long | 主键 | 自增 |
| name | String | 技能名称 | 非空，唯一 |
| visibility | SkillVisibility | 可见性 | 默认 PRIVATE |
| **teamId** | **Long** | **团队ID（新增）** | **可为空** |
| createdBy | String | 创建者ID | - |
| ... | ... | 其他字段 | - |

### 2.3 数据库设计

**表**: skills

`sql
-- 添加 team_id 字段（不创建外键）
ALTER TABLE skills 
ADD COLUMN team_id BIGINT NULL AFTER created_by;

-- 添加索引提升查询性能
CREATE INDEX idx_skills_team_id ON skills(team_id);
`

### 2.4 权限逻辑设计

#### 2.4.1 查看权限 (canViewSkill)

| 可见性 | 允许查看的用户 |
|--------|---------------|
| PUBLIC | 所有用户 |
| PRIVATE | 仅创建者 |
| TEAM | 团队成员（members字段包含用户ID） |

#### 2.4.2 修改权限 (canWriteSkill)

| 可见性 | 允许修改的用户 |
|--------|---------------|
| PUBLIC | 创建者或平台管理员 |
| PRIVATE | 仅创建者 |
| TEAM | 创建者或团队创建者 |

## 3. API 设计

### 3.1 创建技能

**POST** /api/skills

请求体：
`json
{
  "name": "团队技能示例",
  "description": "团队成员共享的技能",
  "type": "API",
  "configuration": "{...}",
  "visibility": "TEAM",
  "teamId": 1,

| 字段 | 类型 | 含义 | 必填 |
|------|------|------|------|

| teamId | Long | 团队ID（visibility=TEAM时必填） | 条件必填 |

## 4. 数据一致性保障

### 4.1 业务层校验

| 校验场景 | 校验内容 | 错误处理 |
|----------|----------|----------|
| 创建TEAM技能 | teamId不能为空 | 返回400错误 |
| 创建TEAM技能 | teamId对应的团队必须存在 | 返回400错误 |
| 创建TEAM技能 | 用户必须是团队成员 | 返回403错误 |
| 更新visibility | 从TEAM改为其他时，teamId置空 | 自动处理 |
| 更新visibility | 改为TEAM时，校验团队存在性 | 返回400错误 |

### 4.2 团队删除处理

当团队被删除时，关联的技能需要处理：

| 处理方式 | 说明 |
|----------|------|
| 改为PRIVATE | 技能归创建者所有 |
| 直接删除 | 删除所有关联技能 |

建议采用**改为PRIVATE**的方式，避免数据丢失。

## 5. 安全性考虑

### 5.1 权限隔离

- 用户只能查看自己有权限的技能
- 用户只能修改自己创建的技能或自己是管理员的团队技能
- 团队技能的成员验证基于 user_team.members 字段

### 5.2 输入验证

- 验证 	eamId 是否为有效数字
- 验证 isibility 是否为合法值
- 防止SQL注入（MyBatis参数化查询）

## 6. 性能考虑

### 6.1 索引优化

`sql
-- 为团队技能查询添加索引
CREATE INDEX idx_skills_team_id ON skills(team_id);
CREATE INDEX idx_skills_visibility_team ON skills(visibility, team_id);
`

### 6.2 查询优化

团队成员查询可能涉及字符串匹配（members字段为逗号分隔），建议：
- 使用 LIKE '%userId%' 查询
- 如果性能问题严重，可考虑引入中间表 user_team_member

## 7. 向后兼容性

- 现有技能的 	eamId 为 NULL，不影响功能
- 现有 API 端点无需修改
- 数据库字段新增为可空，不影响现有数据
